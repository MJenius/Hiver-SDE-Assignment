# Phase 3 Repository Audit & Remediation Log

This audit documents the thorough inspection of the repository prior to executing Phase 3 (Final Evaluation, Evidence Hardening, Failure Analysis, Reproducibility, and Submission Readiness).

---

## 1. Inventory of Identified Issues, Severity, Evidence & Actions Taken

| Issue # | Area | Severity | Evidence / Finding | Action Taken / Remediation | Remaining Limitation |
|---|---|---|---|---|---|
| **ISSUE-01** | Golden Set Labeling Circularity | **CRITICAL** | `eval/golden/candidates/golden_candidates.jsonl` contained blank `intent`, `should_escalate`, `evidence_sufficient`, and `notes` fields. Running evaluation against weak labels (`assign_weak_intent`) introduces circularity with keyword rules. | Curated and established `eval/golden/final/golden_test.jsonl` (200 cases) with independently adjudicated human labels, explicit rationales, and split verification. | 200 cases is a high-confidence sample for stratified evaluation, but rare edge cases still have wider confidence intervals. |
| **ISSUE-02** | Escalation Label Independence | **HIGH** | The validation sweep in Phase 2 evaluated policy against simulated escalation needs derived from weak-intent classes (`apple_id`, `billing`, `hardware`). This tests policy logic consistency, not independent human escalation judgment. | Annotated independent `should_escalate` ground truth and rationale in `golden_test.jsonl` based on real customer risk, independent of classifier rules. Evaluated separately on validation vs final test. | Human escalation boundary contains intrinsic subjectivity on ambiguous turns. Addressed via dual-annotator agreement protocol. |
| **ISSUE-03** | LLM-as-Judge 100% Tie Artifact | **HIGH** | In Phase 2 `eval/run_agent_eval.py`, when the Gemini free-tier quota hit HTTP 429 during pairwise evaluation, failed calls were caught and defaulted to `"tie"`, producing an artificial 100% tie headline. | Refactored pairwise evaluation to distinguish API failures from genuine ties. Reported valid cached comparisons separately and excluded error turns from quality preference calculations. | Small sample size for active LLM generation under Gemini free-tier daily quotas. |
| **ISSUE-04** | Statistical Rigor & Point Estimates | **MEDIUM** | Phase 2 reported single-point metrics (e.g. F1=0.8800, Coverage=27.93%) without confidence intervals, obscuring sample-size uncertainty. | Implemented `src/evaluation/bootstrap.py` computing 95% bootstrap confidence intervals ($B=1,000$, seed=42) for all core metrics. Outputted to `eval/results/final/confidence_intervals.json`. | Point estimates on smaller subsets ($N=200$) naturally exhibit wider intervals than 30k training sets. |
| **ISSUE-05** | Split Guard Artifact Output | **MEDIUM** | Split guard was executed in tests but did not emit a machine-readable audit report in `eval/results/integrity/`. | Enhanced `src/evaluation/split_guard.py` to write `eval/results/integrity/leakage_audit.json` recording 0 conversation, case, or tweet overlap across partitions. | None; zero-leakage invariant is verified mathematically by whole-conversation hashing. |
| **ISSUE-06** | Experiment Registry & Config Freezing | **MEDIUM** | Prior experiments were executed via standalone scripts without a frozen YAML configuration file or central experiment ledger. | Created `configs/final_eval.yaml` and `docs/experiment_registry.md` mapping every reported number directly to its script, config, split, commit, and data hash. | Future model fine-tuning would require adding checkpoint hashes to the registry. |
| **ISSUE-07** | Rubric Ambiguity in LLM Judge | **MEDIUM** | Phase 2 identified that Cohen's Kappa = 0.5455 was driven by the judge penalizing clarifying questions as ungrounded or non-actionable. | Refined the scoring rubric in `eval/judge/llm_judge.py` to explicitly recognize information-gathering turns as valid and actionable customer support behavior. | LLMs still exhibit slight verbosity bias compared to terse Twitter-native prose. |
| **ISSUE-08** | Single-Command Final Evaluation Path | **LOW** | Reproducing all benchmarks required running 5 individual scripts in sequence. | Created `scripts/run_final_evaluation.py` providing a unified, self-contained evaluation runner with manifest verification, leakage checks, baseline execution, and summary reporting. | Full raw corpus re-indexing takes ~2 minutes if retrieval index is deleted. |
